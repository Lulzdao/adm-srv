# adm-srv

Внутренняя административная платформа: служба заявок (хелпдеск) с
встроенными модулями — реестр сертификатов, журнал звонков АТС и
мессенджер организации.

## Структура репозитория

```
adm-srv/
├── helpdesk-backend/   ← платформа/админ-панель (хелпдеск + вход + прокси модулей)
├── CERTVIEWER/         ← модуль «Сертвивер» (реестр сертификатов)
├── SMDR/               ← модуль «Журнал звонков» (сборщик SMDR + веб-интерфейс)
└── MESSENGER/          ← модуль «Искра» (сервер мессенджера + десктоп-клиент)
```

Все четыре приложения — независимые Node.js-процессы, которые запускаются
и деплоятся по отдельности (каждый на своём порту), но лежат в одном
дереве проектов, потому что `helpdesk-backend` встраивает остальные три
как модули: проксирует к ним запросы через `helpdesk-backend/config/modules.js`
и `helpdesk-backend/routes/modules.js`, проверяя вход и роль пользователя
до того, как запрос уйдёт в модуль. Сами модули слушают только
`127.0.0.1` и ничего не знают про логин — см. `helpdesk-backend/README.md`.
Исключение — MESSENGER, см. ниже.

## helpdesk-backend

Платформа целиком: LDAP-аутентификация в двух доменах, роли по членству
в AD-группах, тикеты по отделам (ИТ/ХОЗ/ЕГРПО), уведомления, панель
администрирования и реестр подключённых модулей. Подробности —
`helpdesk-backend/README.md`.

## CERTVIEWER

Реестр сертификатов: разбирает PEM/DER-сертификаты, извлекает ФИО,
СНИЛС/ИНН и срок действия. Порт по умолчанию — 3101. Подробности —
`CERTVIEWER/README.md`.

## SMDR

Журнал звонков с АТС Panasonic KX-TDE200: `collector.py` собирает данные
по протоколу SMDR (TCP) и пишет в SQLite, `web-node` — веб-интерфейс
(журнал, статистика, справочник добавочных), порт по умолчанию — 3102.
Подробности — `SMDR/README.md`.

## MESSENGER

Мессенджер организации (бренд «Искра»): Node.js + Express + WebSocket +
SQLite, свой логин/пароль и права (`can_admin`/`can_broadcast`) — не связаны
с LDAP-ролями платформы. Порт по умолчанию (после переноса под платформу) —
3103. Веб-страница сервера — это панель администратора мессенджера, а не
чат; сотрудники работают через десктоп-клиент (Electron, `desktop-client/`).
Подробности — `MESSENGER/README.md`.

Интегрирован в платформу иначе, чем CERTVIEWER и SMDR: под прокси
(`/modules/messenger`, только для роли `it`) доступна только веб-панель
администратора, и вход в неё остаётся собственный, мессенджера — второй
логин поверх входа в платформу, ничего не убирали и не встраивали в LDAP.
Десктоп-клиенты сотрудников подключаются к серверу мессенджера напрямую по
сети (WebSocket), в обход платформы и её логина — поэтому, в отличие от
остальных модулей, сам процесс **нельзя** ограничивать `127.0.0.1`: он
по-прежнему должен слушать реальный сетевой адрес, только на новом порту
3103 (3000 теперь занят самим `helpdesk-backend`). При обновлении адреса
сервера не забудьте `MESSENGER/desktop-client/config.js` (`SERVER_URL`) —
или пересобрать инсталлятор клиента, или раздать сотрудникам новый адрес
через Ctrl+S на экране входа (см. `desktop-client/README-desktop-client.md`).

Известное ограничение: живой счётчик «сейчас в сети» на вкладке «Обзор»
панели администратора использует отдельный WebSocket на `location.origin`
(без префикса `/modules/messenger`) — платформа сейчас проксирует только
обычные HTTP-запросы, апгрейд до WebSocket через `routes/modules.js` не
прокидывается. Остальная часть панели (пользователи, отделы, права,
переписки, рассылки, файлы) работает полностью, просто без live-обновления
этого одного счётчика. Донастроить проксирование WS — отдельная задача,
если/когда понадобится.

## Разворачивание

Каждое приложение — `npm install`, затем `.env.example` → `.env` со своими
значениями. `SMDR/web-node` уже настроен только под работу за платформой
(своего логина нет). `CERTVIEWER` по умолчанию (`BEHIND_GATEWAY=false`)
всё ещё работает как самостоятельное приложение со своим логином —
переключить на `BEHIND_GATEWAY=true`, когда проверите прокси со стороны
платформы. `MESSENGER` работает как раньше, со своим логином — платформа
только проксирует к нему запросы и решает, кому показывать пункт меню.
Реальные данные (`*.db`, `uploads/`, `.env`, `MESSENGER/bootstrap-admin.js`)
в репозиторий не входят — см. `.gitignore`.
