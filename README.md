# adm-srv

Внутренняя административная платформа: служба заявок (хелпдеск) с
встроенными модулями — реестр сертификатов и журнал звонков АТС.

## Структура репозитория

```
adm-srv/
├── helpdesk-backend/   ← платформа/админ-панель (хелпдеск + вход + прокси модулей)
├── CERTVIEWER/         ← модуль «Сертвивер» (реестр сертификатов)
└── SMDR/               ← модуль «Журнал звонков» (сборщик SMDR + веб-интерфейс)
```

Все три приложения — независимые Node.js-процессы, которые запускаются
и деплоятся по отдельности (каждый на своём порту), но лежат в одном
дереве проектов, потому что `helpdesk-backend` встраивает остальные два
как модули: проксирует к ним запросы через `helpdesk-backend/config/modules.js`
и `helpdesk-backend/routes/modules.js`, проверяя вход и роль пользователя
до того, как запрос уйдёт в модуль. Сами модули слушают только
`127.0.0.1` и ничего не знают про логин — см. `helpdesk-backend/README.md`.

## helpdesk-backend

Платформа целиком: LDAP-аутентификация в двух доменах, роли по членству
в AD-группах, тикеты по отделам (ИТ/ХОЗ/ЕГРПО), уведомления, панель
администрирования и реестр подключённых модулей. Подробности —
`helpdesk-backend/README.md`.

## CERTVIEWER

Реестр сертификатов: разбирает PEM/DER-сертификаты, извлекает ФИО,
СНИЛС/ИНН и срок действия. Порт по умолчанию — 3101. Подробности —
`CERTVIEWER/README.md`.

## SMDR

Журнал звонков с АТС Panasonic KX-TDE200: `collector.py` собирает данные
по протоколу SMDR (TCP) и пишет в SQLite, `web-node` — веб-интерфейс
(журнал, статистика, справочник добавочных), порт по умолчанию — 3102.
Подробности — `SMDR/README.md`.

## Разворачивание

Каждое приложение — `npm install`, затем `.env.example` → `.env` со своими
значениями. `SMDR/web-node` уже настроен только под работу за платформой
(своего логина нет). `CERTVIEWER` по умолчанию (`BEHIND_GATEWAY=false`)
всё ещё работает как самостоятельное приложение со своим логином —
переключить на `BEHIND_GATEWAY=true`, когда проверите прокси со стороны
платформы. Реальные данные (`*.db`, `uploads/`, `.env`) в репозиторий не
входят — см. `.gitignore`.

## В планах

Подключение сервера мессенджера как ещё одного модуля платформы —
по той же схеме (отдельный процесс на `127.0.0.1`, проксирование через
`routes/modules.js`, доступ по ролям).
