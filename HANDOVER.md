# Где мы остановились

Файл-закладка для продолжения работы в другой сессии. Контейнер, в котором идёт
разработка, эфемерный: всё, чего нет в git, пропадает. Поэтому здесь записано
состояние на момент паузы и то, с чего продолжать.

**Дата паузы:** 2026-08-27
**Ветка:** `claude/messenger-module` (PR #2)

## Что сделано и лежит в репозитории

### Раздел оповещений — закончен целиком

Четыре этапа из согласованного концепта, все в коде и проверены:

1. Почта настраивается из панели (`services/mailer.js`), проверка соединения,
   пробное письмо, журнал доставок.
2. Модель «событие отдельно от доставки»: `notification_events` +
   `notification_deliveries` + `notification_settings`, справочник категорий в
   `config/notifications.js`. Заявки переведены на неё.
3. Планировщик (`services/scheduler.js`) без внешних зависимостей, пороги
   30/20/10/5 и «истёк» (`services/sources/certs.js`).
4. Исходящие минуты за месяц (`services/sources/smdr.js`).

Подробности — в `helpdesk-backend/README.md`, раздел «Оповещения».

Оснастка в `helpdesk-backend/test/helpers/` и `CERTVIEWER/test/zipFixture.js`:

- `zipFixture.js` — сборка ZIP руками, включая намеренно испорченные.

**Все данные в тестах выдуманы.** Настоящих сертификатов, доверенностей и
адресов в тестах нет и быть не должно.

### Мелкие правки по ходу

- `scripts/test-ldap.js` → `scripts/check-ldap.js`. Старое имя совпадало с
  шаблоном встроенного запускателя тестов: `node --test` подхватывал
  диагностическую утилиту как набор тестов и падал на машине без домена.
- `config/modules.js`: адреса Сертвивера и журнала звонков переопределяются
  `MODULE_CERTS_URL` / `MODULE_SMDR_URL`. Нужно и для тестов, и на случай, если
  модуль стоит не на этой машине (для «Искры» такая переменная уже была).
- `package.json`: добавлен `npm test`. Именно `node --test` без аргумента —
  `node --test test/` пытается выполнить каталог как файл.

## На чём остановились

Шёл **аудит всего проекта** — то, что заказывал пользователь: архитектура,
поиск дефектов с конкретными правками, тесты, оптимизация, приоритеты.

Аудит выполнялся как workflow из восьми направлений с адверсариальной проверкой
каждой находки. **Сценарий сохранён в `.claude/workflows/audit.js`** — его можно
запустить заново, не пересобирая:

```
Workflow({ scriptPath: ".claude/workflows/audit.js" })
```

Направления: заявки, фронтенд платформы, сервисы, маршруты и вход, Сертвивер,
журнал звонков, сквозные проблемы (дублирование/мёртвый код/хардкод),
производительность и схема данных.

Результаты того запуска **не сохранились** — он не успел закончиться до паузы, а
живут они только в контейнере. Это не потеря: аудит воспроизводится запуском
сценария, а код с тех пор не менялся.

## С чего продолжать

1. **Запустить аудит** сценарием выше и разобрать находки по приоритетам:
   сначала дефекты и дыры, потом архитектура, потом мелочи.
2. **Дописать тесты** по тем местам, которые аудит отметит как рискованные.
   Незакрытые сейчас участки, которые видно и без аудита:
   - `routes/tickets.js` — права доступа по ролям (`canAccessTicket`), загрузка
     вложений, нумерация заявок;
   - `routes/auth.js` — ограничение попыток входа, локальные аварийные учётки;
   - `services/tls.js` — самый большой сервис, не покрыт совсем;
   - `SMDR/web-node/server.js` — сборка SQL конкатенацией, стоит проверить
     отдельно;
   - интеграционный тест «создали заявку по HTTP → пришло письмо» поверх
     реального Express-приложения.
3. **Не трогать `MESSENGER/`** структурно: это вендоренная копия
   `Lulzdao/Iskra-messenger`, её периодически сливают с upstream. Рефакторинг
   там создаст вечный конфликт слияния.

## Что важно помнить про проект

Ограничения, из которых растут почти все решения:

- **Нет шага сборки.** Фронтенд — чистые HTML/CSS/JS. React рассматривали и
  осознанно отвергли.
- **Нет новых npm-зависимостей** без крайней нужды: сеть изолирована, нативные
  модули не соберутся. Отсюда `node:sqlite`, `node:test`, встроенный `zlib` и
  разбор ZIP руками.
- **Браузеры — Chromium 109.** Никаких `oklch`, `:has()`, веб-шрифтов.
- **Комментарии на русском и объясняют ПОЧЕМУ**, а не что делает строка. Это
  принятый стиль, его стоит держать.
- Из архива МЧД сохраняются **только ФИО, реестровый номер и срок**. Паспорт,
  СНИЛС, ИНН не хранятся намеренно — это решение, а не недоделка.
