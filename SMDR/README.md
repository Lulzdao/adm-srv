# Журнал звонков Panasonic KX-TDE200 — документация

Модуль административной платформы. Собирает данные о звонках с АТС Panasonic
KX-TDE200 по протоколу SMDR (TCP), сохраняет их в базу и отображает в
веб-интерфейсе с фильтрами, статистикой и справочником сотрудников.

Заменяет собой сломанный eSMDR (RS-232), используя вместо него
SMDR-вывод по LAN — новый метод в настройках самой АТС.

Веб-часть встроена в платформу (`helpdesk-backend`): своего входа у неё нет,
слушает только `127.0.0.1:3102`, а вход и роль проверяет платформа до того,
как запрос дойдёт сюда. В сайдбаре у роли `it` появляются три пункта —
Журнал, Статистика, Справочник.

## 1. Архитектура

Система состоит из двух независимых частей, работающих постоянно в фоне:

```
┌─────────────────┐        TCP :23000        ┌──────────────────────┐
│  Panasonic       │ ───────────────────────► │  Collector.Py         │
│  KX-TDE200       │   адрес и пароль SMDR —   │  (Python, служба      │
│  (адрес в .env)  │   из SMDR/.env            │   SMDR_Collector)      │
└─────────────────┘                           └──────────┬───────────┘
                                                           │ пишет в
                                                           ▼
                                                  ┌──────────────────┐
                                                  │   smdr.db          │
                                                  │   (SQLite)          │
                                                  └────────┬─────────┘
                                                           │ читает
                                                           ▼
                                                  ┌──────────────────┐
                                                  │  server.js          │
                                                  │  (Node.js/Express,   │
                                                  │   служба SMDR_Web)   │
                                                  └────────┬─────────┘
                                                           │ HTTP :3102
                                                           │ (только 127.0.0.1)
                                                           ▼
                                              helpdesk-backend (прокси, вход)
                                                           │
                                                           ▼
                                                     Браузер (веб)
```

- **`Collector.Py`** — держит постоянное TCP-соединение к АТС, авторизуется,
  разбирает построчный поток SMDR и пишет каждый звонок в `smdr.db`. При
  обрыве связи переподключается каждые 5 секунд. Ничего не показывает
  пользователю — работает тихо в фоне. Адрес АТС и пароль SMDR берёт из
  `SMDR/.env` (см. `.env.example`); без них не запускается.
- **`server.js`** — веб-интерфейс на Node.js/Express. Читает ту же базу,
  показывает журнал с фильтрами, статистику, справочник добавочных.
  Собственного логина не имеет: слушает только `127.0.0.1`, доступ
  определяет платформа.
- **`smdr.db`** — общая база SQLite, лежит в `C:\SMDR\smdr.db`,
  используется обоими процессами одновременно.

Оба процесса подняты как **службы Windows через NSSM** — стартуют сами
при загрузке компьютера, не требуют открытых окон терминала.

## 2. Дерево файлов на сервере

```
C:\SMDR\
│
├── Collector.Py            ← сборщик звонков (Python, стандартная библиотека —
│                              venv/pip install не нужны, см. раздел 6)
├── .env                      ← адрес АТС и пароль SMDR (не коммитится)

├── smdr.db                    ← база данных (общая для Collector.Py и веба)

└── web-node\                  ← веб-интерфейс (Node.js)
    ├── server.js                ← основной сервер (роуты, API)
    ├── db.js                    ← подключение к smdr.db + функция lower_ru
    ├── package.json
    ├── .env                     ← порт (по умолчанию 3102); больше настраивать нечего
    ├── node_modules\
    ├── views\
    │   ├── dashboard.ejs          ← журнал звонков (главная страница)

        └── style.css               ← все стили (тема Material You)
```

## 3. Настройки АТС (не менять без необходимости)

В Maintenance Console: **Maintenance → Main → System → SMDR Options**

| Параметр | Значение |
|---|---|
| Output method | LAN |
| Destination IP | IP хоста Windows, где крутится `Collector.Py` |
| Port | 23000 |
| Outgoing/Incoming Call Print | Print |

АТС шлёт `\r\n`-разделённые строки и требует логин и пароль сразу после
подключения. Их значения задаются в `SMDR/.env` (`SMDR_LOGIN`,
`SMDR_PASSWORD`) — в коде и в этом файле пароля нет специально. У Panasonic
пароль SMDR по умолчанию общеизвестен; если его ни разу не меняли, смените
на АТС и пропишите новый в `.env`.

**Важно:** АТС разрешает только одно активное подключение к SMDR-порту
одновременно. Если запущено два коллектора (или тестовый скрипт +
основной) — АТС будет рвать соединения. Держите запущенным только
`Collector.Py` как службу.

## 4. Формат данных SMDR (как он разбирается)

Примеры сырых строк, которые шлёт АТС:

```
06/08/26 08:54  3011 06 <D>358623<I>984742420323  0'03 00:01'21        ← входящий
06/08/26 08:54  2042 30 89610358265                    00:00'34        ← исходящий
06/08/26 08:55  1016     EXT4041                                       ← внутренний
06/08/26 09:06  2091 13 <D>358601<I>989997501396  0'04 00:00'00  NA    ← пропущенный
```

Разбор (`Collector.Py`, функция `parse_line`):

| Поле | Что значит |
|---|---|
| `ext` | Добавочный, на котором произошло событие |
| `co` | Номер линии/транка |
| `<D>...<I>...` | Входящий: `D` — DID-номер (куда звонили), `I` — номер звонящего |
| `EXTxxxx` | Внутренний звонок — на какой добавочный переведено |
| `ring` | Время до ответа (например `0'04` = 4 сек) |
| `duration` | Длительность разговора `ЧЧ:ММ'СС` |
| `NA` (status) | No Answer — звонок не был отвечен (используется для бейджа "Пропущенный") |

Строки, которые не подошли ни под один шаблон, не теряются — сохраняются
в БД с `direction = 'unknown'`, и попадают в `collector.log` с пометкой
`НЕ РАСПОЗНАНО:`. Если такие появляются в логе — по конкретной сырой строке
дописывается регулярное выражение `LINE_RE` в `Collector.Py`.

## 5. База данных (таблица `calls`)

| Поле | Описание |
|---|---|
| `call_dt` | Дата+время звонка в формате `YYYY-MM-DD HH:MM:00` (секунд АТС не передаёт) |
| `ext` | Добавочный |
| `co` | Линия |
| `direction` | `outgoing` / `incoming` / `internal` / `unknown` |
| `did`, `caller` | Для входящих: DID-номер и номер звонящего |
| `internal_to` | Для внутренних: на какой добавочный переведено |
| `number` | Для исходящих: набранный номер |
| `ring`, `duration` | Ожидание ответа / длительность разговора |
| `status` | `NA` для пропущенных, иначе пусто |
| `raw_line` | Исходная строка от АТС (для отладки) |

Таблица `employees` — простой справочник `ext → fio`, заполняется вручную
через страницу "Справочник" в вебе.

## 6. Управление службами (NSSM)

Обе службы — `SMDR_Collector` (Python) и `SMDR_Web` (Node.js) —
запускаются автоматически при старте Windows.

`Collector.Py` использует только стандартную библиотеку Python
(`socket`, `sqlite3`, `time`, `re`, `logging`, `datetime`) — сторонних
пакетов нет вообще, поэтому отдельное виртуальное окружение (`venv`) ему
не нужно и ничего не даёт. Служба `SMDR_Collector` в NSSM должна
указывать в поле **Application** прямо на системный `python.exe`
(посмотреть путь: `where python` в командной строке), без каких-либо
`venv\Scripts\python.exe`.

```
nssm start   SMDR_Collector       — запустить
nssm stop    SMDR_Collector       — остановить
nssm restart SMDR_Collector       — перезапустить

nssm start   SMDR_Web
nssm stop    SMDR_Web
nssm restart SMDR_Web
```

Или через **Панель управления → Администрирование → Службы**
(`services.msc`) — там же можно посмотреть, запущены ли они,
и настроить через GUI.

### Когда нужен перезапуск службы

| Что поменяли | Нужен ли рестарт |
|---|---|
| `Collector.Py` | Да — `nssm restart SMDR_Collector` |
| `server.js`, `db.js` | Да — `nssm restart SMDR_Web` |
| `.ejs` (шаблоны страниц), `.css`, `.js` во `public\` | Нет — просто обновить страницу в браузере |
| `package.json` (добавили новую библиотеку) | Да, и перед этим `npm install` |

## 7. Типовые проблемы и решения

**Пункт «Журнал звонков» в платформе открывается с ошибкой «Модуль временно
недоступен»**
→ Значит платформа не достучалась до `127.0.0.1:3102`. Проверьте
`nssm status SMDR_Web` в CMD, посмотрите на вкладке "I/O" в настройках
службы, куда пишутся stdout/stderr — там будет текст ошибки Node. Проверить
модуль напрямую с самого сервера: `curl http://127.0.0.1:3102/`.

**В `collector.log` постоянно "Обрыв связи: АТС закрыла соединение"**
→ Скорее всего где-то ещё открыто второе подключение к порту 23000
(например, забытое тестовое окно PowerShell). АТС не пускает второе
подключение одновременно. Закройте лишние подключения, оставьте
только службу.

**Пропущенные звонки не помечаются бейджем**
→ Проверяйте по полю `status = 'NA'`, а не по нулевой длительности —
нулевая длительность бывает и у отвеченных звонков (разговор доли секунды).

**Веб не находит `smdr.db`**
→ `db.js` ищет базу по относительному пути `../smdr.db` от папки
`web-node`. Структура папок должна быть строго `C:\SMDR\smdr.db` +
`C:\SMDR\web-node\`, не переносите `web-node` в другое место без
правки пути в `db.js`.

**После `npm install` ошибка компиляции `better-sqlite3` (нужен Visual Studio)**
→ Значит версия пакета в `package.json` не имеет готового бинарника
под установленную версию Node.js. Проверьте `node --version` и
актуальную поддержку `better-sqlite3` на npm — возможно, нужно
поднять версию пакета в `package.json`.

**Статистика (графики) не грузится**
→ `Chart.js` подключается с локального сервера (`/vendor/chart.umd.js`,
раздаётся из `node_modules/chart.js/dist`), а не с внешнего CDN —
специально, чтобы не зависеть от блокировок в сети. Если всё равно
не грузится — проверьте, что `chart.js` есть в `node_modules`
(`npm install` после обновления `package.json`).

## 8. Доступы

- **SMDR (АТС → коллектор):** логин и пароль задаются в `C:\SMDR\.env`
  (`SMDR_LOGIN`, `SMDR_PASSWORD`) вместе с адресом АТС (`SMDR_HOST`).
  Файл `.env` в репозиторий не попадает; без него коллектор не стартует.
  Смена — правка `.env` + `nssm restart SMDR_Collector`.
- **Веб-интерфейс:** своего логина нет. Вход и роль проверяет платформа
  (`helpdesk-backend`), модуль слушает только `127.0.0.1:3102` и снаружи
  недоступен. Кому открыт пункт меню — задаётся в
  `helpdesk-backend/config/modules.js` (сейчас роль `it`).

## 9. Принципы при доработках

Разделение частей менять не стоит: `Collector.Py` только собирает и разбирает
сырые данные в БД, `web-node` только читает БД и отображает. Напрямую друг с
другом они не общаются — только через `smdr.db`.

Веб-часть рассчитана на работу за платформой: не добавляйте в неё
собственный логин и не снимайте привязку к `127.0.0.1` — иначе журнал
звонков окажется доступен из сети без какой-либо проверки.

Таблицы журнала дорисовываются на клиенте через `innerHTML`
(`dashboard.ejs`, `stats.ejs`), поэтому любые значения из базы там надо
пропускать через `escHtml()` — ФИО в справочник вводит человек, и без
экранирования это готовый XSS. В серверных шаблонах для того же годится
обычный `<%= %>` (он экранирует сам), а `<%- %>` — только для include.
