# Реестр сертификатов — установка на Windows

## 1. Установка Node.js
Скачать LTS-версию с https://nodejs.org и установить (галка "Add to PATH" по умолчанию включена).

## 2. Развёртывание проекта
Скопировать папку `certviewer` целиком на сервер, например в `C:\apps\certviewer`.

Открыть PowerShell / cmd в этой папке и выполнить:
```
npm install
```
Все зависимости чистые (без нативных C++-модулей), компилятор/Visual Studio не требуются в любом случае.

## 2.1. Настройка логина
Скопировать `.env.example` в `.env` (в той же папке) и задать свои значения:
```
copy .env.example .env
```
Открыть `.env` в блокноте и поменять `ADMIN_USERNAME`, `ADMIN_PASSWORD` и `SESSION_SECRET`
на свои — это логин/пароль для входа в веб-интерфейс. Файл `.env` не должен попадать
никуда за пределы сервера (в архивы, репозитории и т.п.), там реальный пароль.

Если `.env` не создать — сервер запустится с логином/паролем по умолчанию
(`admin` / `change-me`) и выведет предупреждение в консоль. Работать будет,
но это небезопасно — обязательно задайте свои значения перед реальной эксплуатацией.


## 3. Запуск
```
npm start
```
Сервер поднимется на порту 3000: http://localhost:3000
Порт можно поменять переменной окружения `PORT`, например:
```
set PORT=8080 && npm start
```

## 4. Автозапуск как служба Windows
Проще всего через уже знакомый вам NSSM:
```
nssm install CertViewer "C:\Program Files\nodejs\node.exe" "C:\apps\certviewer\server.js"
nssm set CertViewer AppDirectory "C:\apps\certviewer"
nssm start CertViewer
```

## 5. Данные
Все данные хранятся в одном файле `certificates.db` (SQLite) рядом с `server.js`.
Модуль для работы с SQLite (`node:sqlite`) встроен в сам Node.js начиная с версии 22.13 —
никаких npm-пакетов и компиляции не требуется, поэтому вопрос с Visual Studio /
node-gyp больше не всплывёт независимо от версии Node на сервере.

Для бэкапа достаточно скопировать файл `certificates.db` — например тем же
скриптом, что делали для SMDR-базы. При запуске сервер выведет в консоль
`ExperimentalWarning: SQLite is an experimental feature` — это не ошибка,
просто пометка Node.js, программа при этом работает штатно.

## 6. Формат сертификатов
Поддерживаются файлы в формате PEM (текстовый, начинается с `-----BEGIN CERTIFICATE-----`)
и DER (бинарный, обычно `.cer`/`.crt`). Извлекаются:
- **ФИО** — из атрибутов Surname/GivenName сертификата, либо из Common Name, если их нет;
- **Идентификатор** — из атрибута subject `serialNumber` (СНИЛС/ИНН на квалифицированных
  сертификатах), либо серийный номер самого сертификата, если такого атрибута нет;
- **Срок действия** — даты `notBefore` / `notAfter` из сертификата.

Если на реальных сертификатах, которые вы будете загружать, ФИО или идентификатор
извлекаются не в те поля (структура может отличаться у разных УЦ — КриптоПро,
Rutoken, Госуслуги и т.д.) — пришлите мне один такой файл (можно обезличенный тестовый),
подправлю логику парсинга под конкретный формат.
