# Мини-мессенджер — сервер

Self-hosted сервер организации: Node.js + WebSocket + SQLite. Люди работают через десктоп-клиент
(папка `desktop-client/`), а веб-страница сервера — это **панель администратора**, а не чат.

## Запуск

```bash
npm install
```

Перед первым запуском создайте стартового администратора — скопируйте
`bootstrap-admin.example.js` в `bootstrap-admin.js` и укажите свои логин/пароль:

```bash
cp bootstrap-admin.example.js bootstrap-admin.js
# отредактируйте bootstrap-admin.js — свои логин и пароль
JWT_SECRET="замените-на-свой-случайный-ключ" npm start
```

Первый запуск создаст `messenger.db` (SQLite) автоматически, а также — если в системе ещё нет ни
одного администратора — создаст его из `bootstrap-admin.js`. Дальше: войдите под этой учёткой,
создайте через панель реальных администраторов, и стартовую учётку можно (и нужно) удалить — файл
`bootstrap-admin.js` при этом можно оставить на диске: повторно он ничего не создаст, пока в
системе есть хотя бы один администратор.

Откройте `http://localhost:3000` (или адрес сервера в сети) — увидите вход в панель администратора.

⚠️ Меняли схему базы (роли, отделы, отображаемые имена)? Если у вас уже есть `messenger.db` от
более старой версии сервера — удалите файл (`messenger.db`, `messenger.db-shm`, `messenger.db-wal`)
и запустите заново, база пересоздастся с нуля. На боевых данных так делать нельзя — тогда нужна
ручная миграция (`ALTER TABLE`), спросите отдельно, если дойдёт до этого.

**Про сам файл `bootstrap-admin.js`:** не публикуйте его (не коммитьте в общий git-репозиторий,
если он у вас есть) — в нём открытым текстом лежит пароль от первого админа. В `.gitignore` этого
проекта он уже не отслеживается, если вы используете git.

## Панель администратора (веб)

Входить в панель могут только пользователи с правом "Админка" — остальным покажет сообщение и
предложит использовать десктоп-приложение.

Разделы: **Обзор** (кол-во пользователей, сейчас в сети, отделов, сообщений, аптайм сервера),
**Пользователи** (создание пользователей, смена отдела/пароля/**отображаемого имени**, права
"Рассылки"/"Админка" лично каждому, поиск по логину/имени — там же отделы: создание/
переименование/удаление и порядок отображения стрелками ↑↓), **Переписки** (просмотр истории
любого чата, включая файлы + экспорт в .txt), **Рассылка** (сообщение всем + лента + история по
дням/месяцам с поиском), **Файлы** (все файлы, когда-либо отправленные через переписку или
рассылки — кто отправил, куда, когда, сколько весит, с возможностью удалить с диска сервера).

## Права
Два независимых флага, выдаются **только персонально**, каждому пользователю отдельно:
- **can_broadcast** — может отправлять рассылку всем сотрудникам сразу
- **can_admin** — доступ к этой веб-панели

Права нельзя выдать сразу всему отделу — только вручную каждому человеку в разделе "Пользователи".
Отделы служат исключительно для группировки в списке контактов (с настраиваемым порядком
отображения), без какого-либо влияния на права.

Право проверяется свежим из базы при каждом запросе, поэтому изменение действует сразу, без
перелогина.

## Стартовый администратор — почему не "первый зарегистрированный"
Раньше первый зарегистрировавшийся пользователь автоматически становился админом — это гонка: если
сервер оказался доступен в сети до того, как настоящий администратор успел зайти и
зарегистрироваться, администратором мог стать кто угодно, кто окажется быстрее (например, кто-то
из сотрудников открыл клиент раньше, чем вы). То же самое повторилось бы на живом сервере, если
`messenger.db` когда-нибудь пересоздастся (переустановка, случайное удаление файла).

Теперь самостоятельная регистрация никогда не даёт никаких прав — ни рассылок, ни админки, без
исключений. Стартовый администратор создаётся только из файла `bootstrap-admin.js`, который есть
только у того, кто физически имеет доступ к серверу — то есть создание админа больше не зависит от
того, кто быстрее отправит HTTP-запрос.

## Что уже умеет
- Регистрация/вход, пароли хешированы
- Общая комната + личные сообщения 1:1
- Отображаемое имя отдельно от логина (сотрудник сам меняет через профиль в клиенте, админ может
  переименовать любого через панель)
- Presence: 🟢 в сети / 🟡 AFK / ⚪ не в сети, с учётом нескольких ПК на один аккаунт
- Рассылки всей организации
- Передача файлов (загрузка/скачивание защищено токеном)
- Права (рассылки/админка) выдаются лично человеку или сразу всему отделу, без жёсткой системы ролей
- Отделы с настраиваемым порядком отображения
- Стартовый администратор из отдельного конфиг-файла — без гонки за право первой регистрации
- Админ-панель: пользователи, отделы, права, история любой переписки, файлы, статистика

## Что стоит добавить перед боевым использованием
- HTTPS/WSS (через nginx/Caddy как обратный прокси, TLS-сертификат) — сейчас пароли и переписка
  идут в открытом виде, это нормально только в изолированной локальной сети
- Rate-limiting на /api/register и /api/login
- Резервное копирование `messenger.db`

## Деплой на 20–200 человек
Хватит самого дешёвого VPS (1 vCPU / 1 ГБ RAM). Процесс держите через `pm2` или systemd,
чтобы он поднимался заново после падений и перезагрузки сервера.

## Десктоп-клиент
Для сотрудников — см. `desktop-client/README.md`. Веб-страница сервера предназначена только
для администраторов.
